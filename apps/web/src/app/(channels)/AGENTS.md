# web/channels — 몰별 상품등록·품절 송신

`app/(channels)/` 는 우리 상품을 몰로 내보내는 방향을 소유한다. 몰에서 우리 쪽으로
들어오는 주문수집은 `app/(orders)/` 가 소유하며, 두 그룹은 사이드바 '쇼핑몰 관리'
에서만 합쳐 보인다.

- `/mall-channels`: 연결된 몰 현황 허브. 읽기 전용이고 자격증명을 편집하지 않는다.
- `/mall-listings`: 탭 두 개. **등록 현황**은 상품 마스터 × 몰 매트릭스이고,
  **새 등록**은 수집상품에서 출발하는 4단계 마법사다. 기준 엔티티가 다른 것은
  리스팅이 마스터에 걸려 있기 때문이고, 억지로 합치면 둘 중 하나가 빈 표가 된다.
  화면은 몰을 하나도 모른다. 몰을 아는 것은 어댑터뿐이다.
- `/mall-availability`: 일괄 품절·해제. 판정은 재고 도메인 것을 읽기만 한다.
- `/mall-tasks`: 등록·품절 실행 기록을 한 표에서 상태로 본다.

`/mall-settings`(쇼핑몰 계정)는 `app/(orders)/` 에 남아 있다. 그 화면은 주문수집이
소유한 `order_collection` 자격증명을 편집하므로 Orders API 를 쓴다. 사이드바에서 같은
섹션에 있다는 이유로 이 그룹으로 옮기지 말 것.

## 상태 규칙

- 몰별 제약(완전품절=삭제, 비가역 상태, 승인 개입, 전체 재전송, 호출 상한)은 서버
  `MallAdapterManifest` 가 유일한 권위다. 화면에 상수로 다시 적지 않는다.
- 성공은 몰 재조회로 확인된 것(`published`)뿐이다. 전송 완료(`submitted`)를 성공으로
  표시하지 않는다.
- 리스팅을 한 번도 가져오지 않은 몰의 빈 칸은 '몰에 없다'가 아니라 '우리가 모른다'다.
  열과 카드가 `imported` 로 그 차이를 말한다. 모르는 자리에 0 을 찍지 않는다.
- 몰 원문 상태는 도메인(`mall-listing-state.ts`)이 우리 어휘로 접는다. 접히지 않는
  값은 `unknown` 이고, 발행으로도 오류로도 추측하지 않는다. 특히 쿠팡 적재가
  심사중과 반려를 같은 `draft` 로 뭉개므로 그 값은 확인필요로 남긴다.
- 응답이 확인되지 않은 건은 성공에도 실패에도 넣지 않고 `unknown_needs_reconcile`
  로 노출한다.
- 품절 해제는 품절과 같은 명령이다. 별도 화면·별도 버튼 계열로 분기하지 않는다.
- 판매 가능 재고는 `ChannelSkuAvailability` 가 계산한다. 이 그룹에서 용량을 다시
  계산하지 않는다.

## 어댑터 규칙

몰에 보내는 경로는 `_shared/adapters/` 의 `MallPublishAdapter` 구현만 가진다.
몰을 늘리는 일은 그 파일 하나를 더하고 레지스트리에 등록하는 것이고, 화면·상태·
버튼을 몰마다 새로 만들지 않는다.

- 페이지와 컴포넌트는 확장도 몰 엔드포인트도 직접 부르지 않는다. 어댑터만 부른다.
- `kind: 'api'` 몰은 백엔드가 소유한다. 어댑터는 우리 API 를 부른다.
- `extension_form` / `extension_excel` 몰은 브라우저가 소유한다. 몰 관리자 세션이
  브라우저에만 있어 백엔드가 대신 열 수 없다 — 이건 설계 선택이 아니라 제약이다.
- 어댑터는 `ok`(보냈다)와 `confirmed`(등록됐다)를 따로 보고한다. 폼을 채운 것도
  엑셀을 만든 것도 `confirmed` 가 아니다.
- 어댑터는 자기 입력칸을 `fields` 로 선언한다. 화면이 몰별 입력 폼을 하드코딩하지
  않는다. 값의 출처(`master`/`template`/`override`)를 함께 선언해 사람이 무엇이
  상품에서 오고 무엇이 이 몰 고정값인지 보게 한다.
- 사람이 고르는 `override` 값은 **상품에 저장한다**(`manualBasics.mallRegisterValues`,
  공통 칸은 `mallRegisterShared`). 등록할 때마다 다시 받으면 같은 상품인데 몰마다 다른
  값이 들어간다. 저장은 사람이 고친 값만 담는다 — 어댑터 기본값까지 저장하면 기본값을
  고쳐도 저장된 상품이 옛 값에 묶인다(`_shared/mall-register-values.ts`).
- "왜 이 몰에 못 보내는가" 는 `adapter.validate` 만이 답한다. 화면이 몰별 조건을 다시
  적으면 버튼은 열려 있는데 보내면 막히는(또는 그 반대의) 화면이 된다.
- 승인제 몰(`requiresOperatorApproval`)은 확장이 제출하지 않는다. 폼만 채우고
  사람이 누른다.

## 경계 규칙

- 이 그룹의 서버 호출은 `_shared/mall-publishing-api.ts` 를 통한다.
- 파괴적 동작(완전품절, 삭제)은 매니페스트가 허용한 경우에만 버튼이 활성화되고,
  강등된 경우 실제로 보낼 상태를 화면에 표시한다.
