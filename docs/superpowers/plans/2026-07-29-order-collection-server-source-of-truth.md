# Order Collection Server Source of Truth Implementation Plan

> **Superseded behavior (2026-07-29):** The operator-controlled Sellpia
> application plan overrides this document wherever it says unresolved
> transmissions block stock collection or unmatched Rocket final-order rows
> produce HTTP 204/no artifact. Matching records workflow evidence without
> filtering Sellpia candidates.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/order-collection` show the same generated files, counts, deduplication result, and authoritative Sellpia transmission state in every browser within one organization.

**Architecture:** Orders owns an organization-scoped `OrderCollectionArtifact` record containing exact generated bytes and normalized metadata; `SourceImportRun` remains provenance and Coupang PA continues to persist `Order`/`OrderLineItem`. Inventory exposes a narrow read-only port for its existing `SellpiaOrderTransmissionIntent`, while React Query reads the server artifact list and IndexedDB becomes migration-only. Icecream row deduplication moves from localStorage to a short-lived server claim that is completed in the same transaction as artifact persistence.

**Tech Stack:** Prisma 7/PostgreSQL, NestJS 11, Zod and `@kiditem/shared`, Next.js/React 19, TanStack React Query, IndexedDB, Web Crypto SHA-256, Vitest, PG integration tests.

## Global Constraints

- Classify this as an Orders reconstruction across more than 10 files and a 700+ line route component; split new behavior into focused services/hooks instead of adding substantial logic to `OrderCollectionWorkspace.tsx`.
- The only cross-domain exception is an Inventory-owned, read-only Sellpia transmission-status port used by Orders; do not mutate inventory, freshness generations, commitments, or physical stock from Orders.
- Frontend code uses NestJS APIs through `apiClient`; it never sends `organizationId` and never imports Prisma, `pg`, Supabase DB clients, or backend adapters.
- Every server read/write is scoped by `organizationId` from `@CurrentOrganization()`; single-resource operations use `{ id, organizationId }` and return `NotFoundException` when absent.
- Prisma uses `String` plus Zod/domain validation, not native PostgreSQL enums; queried, aggregated, and tenant-guarded fields remain normalized rather than JSON.
- Coupang Rocket PA collection persists every row, links matching
  active-workbook rows as advisory workflow evidence, and persists an artifact
  for every non-empty SHIPMENT or MILKRUN transport. HTTP 204 is reserved for a
  transport with no collected source row.
- Sellpia transmission truth remains `SellpiaOrderTransmissionIntent`; artifact responses project `prepared|finalized|aborted`, and `transmissionRequestedAt` is derived only from `finalizedAt`.
- New server-generated and active client-generated artifacts are transmission eligible; one-time imported IndexedDB history is read/download-only and cannot invoke Sellpia submission.
- Store exact order artifacts in PostgreSQL `Bytes` with a hard 10 MiB limit. Do not use the current public image-oriented `StorageService` for files containing order PII.
- Artifact list responses never include bytes or preview rows. Authenticated file download is on demand with `Cache-Control: private, no-store`; preview parsing remains in the browser.
- Browser extension sessions, auto-detect enabled/interval settings, current modal/filter state, and browser connection errors remain device-local. Shared business history comes from server artifacts and `SourceImportRun`.
- Preserve the order-collection shell order: header/upload modal, five-stage pipeline, daily summary/activity, flat mall grid, optional preview, generated files.
- Preserve per-file action locks, the ordered Sellpia submission queue, upload-evidence requirements, and explicit owner/admin reconciliation before retrying ambiguous submissions.
- The schema change is compatible: keep root `VERSION` at `0.1.29`, run `db:push`, and record “no server-row backfill; optional authenticated browser-history import” in the PR release decision.
- Do not touch the unrelated dirty Channels and `packages/shared/src/schemas/source-import*` changes already present in the workspace.
- All shell commands in this plan use the repository-required `rtk` prefix.

const encoder = new TextEncoder();

export async function fingerprintOrderRows(rows: string[][]): Promise<string[]> {
  return Promise.all(rows.map(async (row) => {

```ts
const IMPORT_KEY_PREFIX = 'kiditem-order-history-imported:';

export function useLocalOrderHistoryMigration({
  organizationId,
  invalidate,
}: {
  organizationId: string | null;
  invalidate: () => Promise<unknown>;
}) {
  const [files, setFiles] = useState<StoredOrderCollectionFile[]>([]);
  const [importing, setImporting] = useState(false);
  const [importedCount, setImportedCount] = useState(0);
  const marker = organizationId ? `${IMPORT_KEY_PREFIX}${organizationId}` : null;

  useEffect(() => {
    let active = true;
    setFiles([]);
    if (marker && window.localStorage.getItem(marker) !== '1') {
      void loadGeneratedOrderFiles().then((loaded) => {
        if (active) setFiles(loaded);
      });
    }
    return () => {
      active = false;
    };
  }, [marker]);

  const importAll = useCallback(async () => {
    if (!marker || importing) return;
    setImporting(true);
    let completed = 0;
    try {
      for (const file of files) {
        await orderCollectionArtifactApi.importLocal(file.blob, file.fileName, {
          mallKey: resolveOrderCollectionMallKey(file) ?? 'legacy-unknown',
          collectionDate: file.collectionDate ?? dayKey(file.convertedAt),
          collectionMode: file.collectionMode ?? 'browser',
          fileKind: file.fileKind ?? 'order',
          sourceName: file.sourceName,
          occurredAt: new Date(file.convertedAt).toISOString(),
          sourceRows: file.sourceRows,
          productRows: file.productRows,
          outputRows: file.outputRows,
          skippedRows: file.skippedRows,
          collectedRows: file.collectedRows ?? null,
          orderNumbers: file.orderNumbers ?? [],
        });
        completed += 1;
        setImportedCount(completed);
      }
      window.localStorage.setItem(marker, '1');
      await invalidate();
      setFiles([]);
    } finally {
      setImporting(false);
    }
  }, [files, importing, invalidate, marker]);

  return { pendingCount: files.length, importedCount, importing, importAll };
}
```

Use `useAuth().user?.organizationId` only for the local marker; never include it in an API request.

| Scenario | Expected authority | Expected result |
|---|---|---|
| Generated file list/statistics | Orders `OrderCollectionArtifact` | Same data in every browser for one organization |
| Exact file re-download | Authenticated Orders artifact bytes | Same SHA-256, no public URL, no bytes in list API |
| Coupang PA orders | Existing `SourceImportRun` + `Order` + `OrderLineItem` | Artifact supplements output evidence without replacing order truth |
| Sellpia requested/finalized state | Inventory `SellpiaOrderTransmissionIntent` | `prepared` blocks ambiguity; `finalizedAt` drives requested state |
| Icecream new-row detection | Orders claimed/seen fingerprints | One winner across concurrent browsers; expired claims recover |
| Auto-detect schedule/session | Current browser and extension | Remains device-local to prevent duplicate schedulers |
| Legacy IndexedDB history | Explicit authenticated import | Shared and downloadable, idempotent by SHA-256, never transmission eligible |
| Other organization access | Server organization predicates | Empty list or 404; no byte/name/status disclosure |
