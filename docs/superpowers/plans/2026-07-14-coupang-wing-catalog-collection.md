# Coupang Wing Catalog Durable Collection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collect a complete, resumable Coupang Wing catalog snapshot from the authenticated Chrome tab and persist bounded, validated chunks in the Channels domain without touching the live catalog.

**Architecture:** A versioned shared contract defines discovery pages, hydrated products, options, media, run status, and browser messages. Channels owns an account-scoped `ChannelScrapeRun` plus idempotent `ChannelScrapeChunk` rows. The MV3 extension performs exact DOM discovery and a fixture-locked detail adapter, uploads deterministic chunks, and resumes from server-reported gaps.

**Tech Stack:** Zod, TypeScript, NestJS, Prisma v7/PostgreSQL, Chrome Manifest V3, plain JavaScript, Node test runner, jsdom, Vitest, Testcontainers.

## Locked Contracts

- Collection source: `coupang_wing_catalog_browser`.
- Collection page type: `catalog_full_snapshot`.
- Collector version for the first adapter: `wing-inventory-v1`.
- Chunk kinds: `discovery_page`, `product_details`, `manifest_confirmation`.
- Discovery chunk sequence is the one-based Wing page number.
- Product detail chunks contain `1..20` contiguous discovery products and stay below `1 MiB`. Sequence is `startOrdinal + 1`; a canonical greedy packer adds the next product only when the result remains within both limits. The payload records `startOrdinal`, so the server can reject a non-deterministic or overlapping batch.
- Manifest confirmation has sequence `1` and contains the first-page fingerprint re-read after hydration.
- Chunk payload maximum is `1 MiB` after canonical UTF-8 JSON serialization; an individual normalized product is limited to `512 KiB`, its allowlisted raw diagnostic object to `64 KiB`, its media array to `100` images, and its option array to `500` options.
- `clientRunKey` is generated by the web client and is unique within `(organizationId, channelAccountId, source)`.
- A recoverable Wing authentication/network error leaves the run `running` and writes diagnostics to `errorJson`. Only invalid identity, conflicting chunks, unstable manifest after a complete retry, or terminal publication validation moves the run to `failed`.
- Collection endpoints never create `SourceImportRun`, `ChannelListing`, `ChannelListingOption`, `ContentWorkspace`, or `ContentAsset` rows.

The canonical hydrated product shape is:

```ts
type CoupangCatalogProductV1 = {
  externalProductId: string;
  registeredName: string | null;
  displayName: string | null;
  category: string | null;
  manufacturer: string | null;
  brand: string | null;
  productStatus: string | null;
  options: Array<{
    externalOptionId: string;
    optionName: string | null;
    skuStatus: string | null;
    modelNumber: string | null;
    barcode: string | null;
    attributes: Array<{ type: string; value: string }>;
    media: Array<CoupangCatalogMediaV1>;
  }>;
  media: Array<CoupangCatalogMediaV1>;
  raw: Record<string, unknown>;
};

type CoupangCatalogMediaV1 = {
  sourceUrl: string;
  role: 'primary' | 'detail' | 'option';
  sortOrder: number;
  externalOptionId: string | null;
};
```

`externalProductId` is the Wing inventory/registered-product ID. `externalOptionId` is the sellable Wing option ID. Missing `legacyCode` is never an error and never substitutes for either identity.
