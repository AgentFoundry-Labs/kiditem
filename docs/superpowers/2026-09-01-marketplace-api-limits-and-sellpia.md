## 1. 한 줄 답

**"API 따오면 된다"와 "쿠팡처럼 하나만 등록" 둘 다 반은 맞다. 정확히는 — 11번가·ESM 모두 주문수집·송장·상품등록·품절재고 4가지가 전부 공식 API로 제공되지만, 어느 몰에도 "대량 일괄 등록/수정" API는 없다. 쿠팡뿐 아니라 11번가·ESM·스마트스토어 전부 1콜=1상품(또는 1옵션)이고, 그 위에 초/분 단위 호출 제한이 걸려 있다.** 그래서 API로 바꾼다고 처리량이 늘지 않는다 — 안정성과 무인화가 늘 뿐이다.

그리고 **셀피아 쪽은 API가 아예 선택지가 아니다.** 셀피아는 셀러용 공개 Open API 문서·신청 절차가 존재하지 않고, 외부 시스템이 셀피아로 주문을 밀어넣는(push) 기능은 어떤 공개 문서에도 없다. 현재 KidItem이 쓰는 화면 주입 방식이 사실상 유일한 경로다.

## 3. 몰별 상세

### 3-1. 11번가

**신청은 쉽다. 심사가 사실상 없다.**
- 절차: 로그인 → `서비스등록·확인 > 서비스등록`에서 사용자정보 입력 → OPEN API KEY 발급. 별도 심사 없음.
- 공식 FAQ 원문: *"판매자회원은 인증키 발급받으면 즉시 사용가능하며"*, *"Seller API 정보 등록시 API사용권한이 즉시 부여되고, 개발가이드 메뉴에 API가 추가 노출됩니다."*
- 대기가 생기는 유일한 경우: 판매자회원 승인 전. *"승인 대기 기간 중 API 가입을 시도하면 '시스템 오류입니다. 관리자에게 문의하여 주십시오.' 라는 안내 문구가 노출될 수 있습니다."*
- **이용료 무료.** *"11번가 오픈 API는 무료로 제공되고 있습니다."*
- 근거: [FAQ](https://openapi.11st.co.kr/openapi/OpenApiFaqBoard.tmall?method=getFaqBoardList&unityBrdNo=55)

**"API도 제한하더라"의 실체 — 4가지다.**

1. **IP 화이트리스트가 사실상의 승인 조건.** *"3. IP 등록하기(셀러API 사용시 꼭 필요함!) … IP주소 정보를 입력해야 셀러 API Key 승인이 가능 합니다."* 입력칸은 개발서버 IP / 개발자 PC / 상용서버 IP 3개, 다중은 세미콜론(`;`) 구분(도매매 실사례 4개, 키위스냅 2개). 미등록 시 *"인증된 IP가 아닙니다."* → [운영 가이드](https://openapi.11st.co.kr/openapi/OpenApiOperationGuide.tmall?operationType=SERVICE_METHOD)

2. **인증키는 계정당 1개.** 약관 제5조 ②: *"회원은 1개의 인증Key만을 발급받아 사용할 수 있으며, 어떠한 경우에도 2개 이상의 인증Key를 발급받거나 그러한 시도를 하여서는 안 됩니다."* → **"수집용 키 / 등록용 키" 분리 불가.** 셀러 ID 1개 = 키 1개 전제로 설계해야 한다. → [약관](https://openapi.11st.co.kr/openapi/OpenApiAgreementInfo.tmall)

3. **일일 호출 상한은 존재하나 수치가 비공개.** 공개 근거는 에러코드 두 줄뿐: *"004 overedTraffic — 하루 호출 가능 회수를 초과했습니다."*, *"005 accessDeny"*. 몇 회인지·리셋 시각·초당 제한·Retry-After 전부 미공개. 약관 제4조는 *"별도의 이용가능 시간 또는 이용가능 회수를 지정할 수 있으며"*, *"회사는 회원에 대하여 API 서비스를 제한하거나 중지할 수 있습니다"* 로 재량을 열어둠. → [개발가이드](https://openapi.11st.co.kr/openapi/OpenApiGuide.tmall)

4. **180일 유효기간 정책이 시행됐다.** 공지 제목 *"[중요] 11번가 OpenAPI 인증키 유효기간(180일) 정책 적용 안내 (6/30 시행)"*. **다만 실무상 무해하다** — FAQ 원문: *"상품 등록/수정/조회 등 API 호출 이력이 발생하면 마지막 호출 시점으로부터 유효기간이 180일 자동 연장됩니다. 180일간 한 번도 사용하지 않은 경우에만 휴면 처리됩니다."* 매일 도는 시스템은 만료되지 않는다.
   - 단, **만료되면 갱신 불가·재발급만 가능하고 기존 키가 즉시 폐기**된다: *"만료된 이후에는 보안 정책상 '갱신'이 불가하며, 오직 '재발급'을 통해서만 다시 사용하실 수 있습니다."* / *"새로운 인증키로 셀링툴 또는 연동 시스템의 정보를 반드시 재설정해야 합니다."* 갱신은 만료 60일 전부터 가능.

**설계에 직접 걸리는 하드 제약 3개**
- 옵션 SKU 전역 유일: *"동일 상품 뿐 아니라 다른 상품에서 사용된 경우에도 중복을 체크하니 참고하시기 바랍니다."* → KidItem 내부 SKU 채번 규칙이 11번가 계정 전체에서 유일해야 한다.
- 기술 스택이 낡음: XML + 헤더 `openapikey:발급key값`, HTTPS 필수, 응답 EUC-KR, 한글 파라미터 UTF-8 인코딩, **이미지 URL에 한글/공백 있으면 등록 실패**.
- **약관 제6조 ④가 걸린다**: *"회원은 API 서비스를 통하여 제공되는 데이터를 연동할 수 있을 뿐이며, API 서비스를 통하여 제공되는 데이터를 복제 또는 저장하거나 전송할 수 없습니다."* 자사 판매 데이터를 자체 DB에 적재하는 KidItem 구조와 **문언상 충돌**. 자기 데이터 운영 목적 캐싱까지 금지 취지인지는 약관만으로 판정 불가 → **대량 적재 설계 전 11번가에 서면 문의 권장.**

### 3-2. ESM(지마켓·옥션)

**여기가 유일하게 "심사에서 떨어질 수 있는" 몰이다.**
- 신청은 웹 폼이 아니라 **이메일**(`etapihelp@gmail.com`). 제출 항목 원문: *"개발 API 범위 / ESM 마스터 ID / 서비스 중인 사이트 Url / **최근 3개월 매출 규모** / API 개발 기간"*.
- 승인 기준이 재량: *"신청 승인은 사이트 검색성능 및 서비스 안정성을 저해하지 않는 수준 내 내부 지원 리소스 한도 내에서 가능합니다."* + *"내부 사정에 따라 신청 하였으나 권한 부여 거절될 수 있음을 미리 양해 부탁 드립니다."*
- **키만 받으면 끝이 아니다**: *"API 개발 완료 후 개발 사항 테스트 완료되면 일정 협의하여 운영에서 실사용하실 수 있습니다."* → 개발완료 → 검수 → 일정협의 게이트가 하나 더 있음.
- 근거: [API 가이드](https://etapi.gmarket.com/pages/API-%EA%B0%80%EC%9D%B4%EB%93%9C)

**좋은 소식: 옥션·G마켓이 진짜로 키 하나다.**
JWT payload `"ssi": "A:옥션판매자ID,G:지마켓판매자ID"` — 콤마로 두 사이트를 한 토큰에 담는다(사이트당 1개씩). 상품등록도 *"양사이트 동시 등록/수정 및 사이트별 개별 등록/수정 모두 가능합니다."* → **1콜에 G마켓+옥션 동시 등록**이 되는 건 4개 몰 중 ESM뿐이다.

**나쁜 소식: 호출 제한이 계속 조여지고 있다.**
- 상품목록 조회: 2024-01 사실상 중단성 제한 → 2024-03 분당 30회 예고 → **2026-08-10 분당 20회**. 초과 메시지: *"상품 조회 수가 1분에 20회를 초과하였습니다."* → [공지](https://etapi.gmarket.com/220)
- 주문조회: **2025-04-23부터 5초당 1회**. 초과 시 `ResultCode 3000`. 단 *"주문번호로 조회하는 경우 제한 없습니다."* → [공지](https://etapi.gmarket.com/198)
- **설계 전제**: 이 수치는 또 내려갈 수 있다고 봐야 한다(2년간 두 번 하향).

**함정 5개 — 이게 진짜 리스크다.** (전부 [/21](https://etapi.gmarket.com/21), [/70](https://etapi.gmarket.com/70) 원문)
1. **재고 0 입력 불가** — `stock`은 *"1~99999까지 입력 가능함"*. 품절은 `isSell=false`로만 표현.
2. **판매중지 1개월 방치 시 상품 자동 삭제** — *"판매중지 상태로 1개월 유지하면 상품삭제"*. 시즌 품절 상품을 그냥 꺼두면 사라진다.
3. **옵션 상품은 재고 API가 안 먹는다** — *"본품만 판매하는 상품만 수정 가능하며 옵션 사용 상품 및 풀필먼트 스타배송 상품은 재고 수정 불가 합니다."*
4. **등록 직후 3분간 가격/재고 수정 불가** — *"상품 등록 API 호출하고 정상 등록 처리 시간(약 3분) 이후 변경할 수 있습니다."* → 등록 파이프라인에 지연 큐 필요.
5. **판매중지 상품은 가격 수정 안 됨** — *"판매중지 상품은 가격 수정되지 않습니다."* → "중지 → 가격변경 → 재개" 순서가 실패한다.

**송장등록은 단건 + 2일 창.** `ShippingDate`는 *"호출시점 2일 이내로 입력 필요"*. 스타배송은 CJ대한통운(10013)·한진(10007)·롯데(10008)로만 가능, 3PL 주문은 API 발송처리 불가. 수정은 별도 API 없이 **같은 API 재호출로 덮어쓰기**.

**스키마 설계 주의**: *"주문/배송/클레임/정산 API는 사이트 상품번호 내려가기 때문에 마스터번호, 사이트별 상품번호를 관리해야 합니다."* → 마스터(goodsNo) ↔ G마켓 상품번호 ↔ 옥션 상품번호 3-way 매핑 테이블이 필수.

### 3-3. 쿠팡 — "하나만 등록"의 실체

**대표님 기억이 정확하다. 그리고 그게 쿠팡만의 특성이 아니다.**

- 상품 생성 `POST .../marketplace/seller-products`의 요청 본문 루트가 **배열이 아니라 단일 상품 객체**다. 여러 상품을 담는 파라미터가 문서에 없다. **100개 상품 = 100회 호출.** → [문서](https://developers.coupang.com/hc/en-us/articles/360033877853-Product-Creation)
- 다만 **1콜에 옵션 200개**까지는 들어간다(*"최대 200개 옵션 등록 가능"*). 즉 "1상품 + 옵션 200개"가 1콜의 최대 단위.

**쿠팡이 다른 몰보다 나은 점 하나 / 나쁜 점 셋**

나은 점 — **송장등록만은 배열을 지원한다.** `orderSheetInvoiceApplyDtos`가 배열이고 응답도 건별 결과(`succeed`, `resultCode`, `retryRequired`)를 돌려준다. 4개 몰 중 유일. 단 **1회 최대 건수가 문서에 없다**(인접 API인 상품준비중 처리는 *"50개 이하 또는 단 건으로 요청해야합니다"*로 명문화 — 준용은 가능하나 근거는 아님).

나쁜 점 1 — **초당 기준이 문서끼리 안 맞는다.**
- 전역 rate limit 정책: *"more than 5 API calls per second"* per vendorId → 429. → [정책](https://developers.coupang.com/hc/en-us/articles/20414599556889-Introduction-of-Open-API-rate-limit-policy)
- 상품 생성 문서: *"상품 생성 및 수정 API는 초당 10건 이하로 호출해 주시기 바랍니다."*
- 쿠팡 스스로 *"Call limit criteria may change depending on the system and vendor ID"*(사전고지 없이 변경). 실무 연동사 윈셀링은 **전 연동에 0.5초(일부 0.25초) 딜레이**를 강제해 초당 2~4콜로 낮춰 운용 중.
- **차단이 영구가 될 수 있다**: *"지속적인 과도한 API호출이 발생할 경우 시스템 자동으로 영구적인 차단이 이루어질 수 있음"*(1차 출처는 쿠팡 공지를 전재한 윈셀링 공지).
- 완충 장치: 임계 약 90%에서 `X-CAG-Warnings` 헤더가 온다 → **이걸 백오프 신호로 쓰면 된다.**

나쁜 점 2 — **일 5,000건 + 계정 총량 상한.**
- *"옵션상품 기준 일 5천 건씩 등록가능합니다."*
- 별도로 `GET .../seller-products/inflow-status`가 `registeredCount` / `permittedCount`(null이면 무제한)를 돌려준다. 문서 예시 8,125 / 10,000. → **등록 루프 전에 이걸 먼저 읽어 남은 슬롯을 계산해야 한다.**

나쁜 점 3 — **승인완료 상품은 상품수정 API가 안 먹는다.** *"승인완료된 상품의 가격 및 재고는 [상품 수정 API]를 사용하시면 반영되지 않습니다."* 재고는 아이템별 수량 API, 판매가는 아이템별 가격 API로 각각 따로. **상품 1개에 옵션 20개면 재고 동기화에 최소 20콜.**

**전략적으로 가장 중요한 한 줄**:
> *"OpenAPI용도의 키는 판매자ID(업체코드) 별로 1개만 발급 가능하며 2개 이상의 연동업체 추가가 불가합니다."* + *"연동업체 1개와 자체개발 1개도 동시 등록이 불가하니 둘 중에 1개로만 선택 등록해야 합니다."* → [FAQ](https://developers.coupang.com/ko/faq/can-i-register-more-than-2-integrators-when-issuing-an-openapi-key)

**즉 쿠팡은 "사방넷 + KidItem 병행"이 불가능하다.** 사방넷을 연동업체로 등록해 둔 상태면, KidItem 자체개발로 키를 바꾸는 순간 사방넷 쿠팡 연동이 끊긴다. **점진 이행이 안 되고 절단 전환(cutover)이 강제되는 유일한 몰.** 연동정보 수정도 *"일주일에 10회 까지만"*(일부 3자 문서는 "월 10회"로 표기 — 불일치).

## 4. 품절·재고 동기화의 현실

**결론부터: "전 상품 실시간 푸시"는 어떤 몰에서도 불가능하다. 4사 전부 구조가 같다 — 1옵션=1콜 단건 API + 초 단위 rate limit.**

실제 숫자로 계산하면:

| 몰 | 단위 | 근거 수치 | 1,000상품 동기화 소요 |
|---|---|---|---|
| 스마트스토어 | 상품 전체 재전송 | 2 RPS, 상품 1건 ≈ 2초 (네이버 개발자 포럼 실측) | **약 2,000초 = 33분** (원문 계산) |
| 쿠팡 | 옵션 1개당 1콜 | 초당 5회 기준 | 옵션 3,000개면 **약 600초 = 10분** *(계산)* |
| ESM | goodsNo 단건 | 상품/재고 API 제한 수치 **미공개** | 1,000콜 *(소요 산출 불가)* |
| 11번가 | 상품/옵션 XML 갱신 | 일일 상한 **미공개** | *(산출 불가)* |

여기에 실패 요인이 겹친다: 쿠팡 429 후 해제까지 *"최소 수분에서 수십분"*, ESM 등록 후 3분 대기, ESM 판매중지 1개월 → 자동삭제, 스마트스토어는 *"현재 커머스API에서는 호출 한도(Quota) 상향 기능을 제공하지 않습니다."*

**→ 강제되는 아키텍처는 하나뿐이다: 전체 스캔 푸시가 아니라, 변경분(델타)만 모아 큐에 넣고 몰별 레이트리밋에 맞춰 백오프하며 흘려보내는 워커.** 이게 통합관리 솔루션들이 "N분 배치"로 도는 이유다.

**단, "사방넷이 10분 배치"라는 건 벤더 공식 문서로 확인하지 못했다.** 확인된 수치는 품고↔사방넷 연동 기준으로 **주문 매시간 30분 / 클레임 10분(최대 20분) / 클레임철회 30분(최대 1시간)** 뿐이다([근거](https://welcome.poomgo.com/guide/sabangnet)). 사방넷·플레이오토·이셀러스 어느 벤더도 "마켓 API 제한 때문에 N분 주기로 돈다"고 스스로 명시한 문서를 찾지 못했다. **"10분 배치"는 구조적 추론이지 인용이 아니다 — 대외적으로 쓰지 말 것.**

**참고로 ESM에만 진짜 실시간 경로가 하나 있다.** 고객이 구매 버튼을 누르는 순간 ESM이 **우리 서버로 재고를 되묻는** XML 콜백(제휴사가 URL을 개발해 제출). *"주문가능할 경우 별도 Notice없이 주문진행시킴, 무응답이어도 주문진행됨"*, *"본 API는 양사 개발 필요하므로 제한적으로 제공합니다."* → 품절 오버셀링을 근본적으로 막는 유일한 수단이지만, 제한적 제공이라 협의 대상. → [G마켓판](https://etapi.gmarket.com/86)

## 5. 셀피아 — 어떻게 보내는가

### 공식 API는 "없다"에 가깝다

- 셀피아 공식 사이트 전 페이지(intro / pricing / sales / addons / order)를 확인했으나 **API·오픈API·개발자센터 항목이 존재하지 않는다.** 부가서비스 목록 전체가 *"스마트 피킹 / 온·오프라인 실시간 재고 조회 / 멀티 배송 / 셀피아 앱 / 자동 주문 수집 / 키오스크"* + 알림톡이 전부. → [addons](https://www.sellpia.com/addons.html)
- `developers.sellpia.com`은 응답하지만 내용이 "구글 크롬 설치하기 / 셀피아 홈페이지 이동" 배너 한 장.
- **다만 `api.sellpia.com`은 살아 있다.** `GET https://api.sellpia.com/` → HTTP 200, `{"message":"Welcome to the Sellpia OpenAPI"}`. 그런데 `/docs`, `/openapi.json`, `/swagger`, `/redoc`, `/v1`, `/orders`, `/token` 등 **문서·스키마 경로 27개 전수 확인 결과 전부 404.** → **존재는 하나 외부 셀러에게 열려 있다는 근거는 0건.** *(비공개/미문서화 상태로 추정)*
- **가장 중요한 공백**: 공개 문서에 **주문 생성/업로드 API 언급이 전혀 없다.** 셀피아 마케팅 문구는 일관되게 "수집(pull)" 방향이고, 외부에서 주문을 밀어넣는(push) 기능은 어떤 페이지에도 없다.

### 셀피아의 "외부 연동"은 사실상 플레이오토 하나다

요금표 '외부 연동' 행은 **택배사 연동 / 플레이오토 연동 지원 / 셀포스 연동** 3개뿐. **사방넷은 표에 아예 없다.** → [pricing](https://www.sellpia.com/pricing.html)

그리고 방향이 반대다. 플레이오토 도움말 원문:
> *"이카운트 ERP, 셀피아 등 제휴 대행사 연동의 경우 별도의 신청 없이 환경설정 내 API 사용 설정으로 가능합니다."*

**즉 셀피아가 API를 내주는 게 아니라, 셀피아가 플레이오토 API를 받아가는 쪽이다.** 제3자(KidItem)가 이 경로에 끼어들 자리가 없다. 플레이오토 API를 직접 쓴다 해도 *"제공되는 API는 조회API이며, 작업API 이용 필요 시 고객센터 문의"* — 쓰기 계열이 막혀 있고, 승인에 **2~5일**, 월 5만원, 작업카운트 별도 차감. → [플레이오토 API](https://www.plto.com/additional/API/)

셀피아의 공식 커스터마이징 경로는 API 문서가 아니라 **유료 개별 개발 계약**이다: *"개발 의뢰 → 기능 정의 → 견적 제시 → 계약 → 입금 → 개발 → 확인"*, *"개발 공수 기준에 따라 별도 비용 발생."*

### 그래서 현재 화면 주입 방식이 최선인가 — **현시점에선 그렇다. 조건 하나 붙여서.**

**그렇다고 보는 이유 3가지**
1. push API가 공개적으로 존재하지 않는다. 대안이 플레이오토 경유인데 그건 조회 전용 + 유료 + 승인제 + 카운트 차감이다.
2. 셀피아 쿼터는 초당 호출수가 아니라 **월 처리 건수(코인)** 모델이다. LITE 주문 500 / STARTER 1,000 / PLUS 5,000 / PRO 20,000, 초과 충전 PLUS 50원·PRO 40원/건, LITE·STARTER는 충전 불가. *"잔여 카운트는 익월로 이월 및 환불되지 않습니다."* → **화면 주입이든 API든 코인은 똑같이 차감된다. API로 바꿔도 비용이 안 줄어든다.**
3. 셀피아 스스로 이 한도를 *"API 주문 카운트"*라고 표기한다(타사 비교표) — 내부는 API인데 셀러에게 열지 않는다는 뜻.

**붙여야 할 조건 하나 — 약관 확인.**
셀피아 이용약관 전문(`/mobile/guide2.html`)이 **HTTP 204 빈 응답**이라 읽지 못했다. **자동화 프로그램·매크로·크롤링 금지 조항이 있는지 확인이 안 된 상태**다. KidItem이 브라우저 확장으로 셀피아 화면을 자동 조작하는 구조이므로, 이건 리스크 관리상 반드시 로그인 후 약관 레이어에서 직접 확인해야 한다.

### 부수적으로 확인된 큰 사실 — KidItem의 진짜 해자

셀피아 몰 목록 API(`https://www-api.plto.com/auth/common/supportMall?solType=gmp`)를 직접 호출해 실측했다(2026-09-02, 총 **139개 몰**):

| 기능 | 지원 몰 수 |
|---|---|
| 주문수집 | 118 |
| 송장전송 | 118 |
| 상품등록 | 90 |
| 상품수정 | 87 |
| 상품품절 | 86 |
| 고객문의 | 68 |
| 발송지연 | 21 |
| **정산수집** | **6** (쿠팡·11번가·옥션·G마켓·롯데ON·SSG 뿐) |

**그리고 139개 전수 검색 결과, 아이스크림몰·온채널·키즈노트·꼬망세·티처몰·키드키즈 — 전부 0건이다.** 셀피아를 아무리 비싼 플랜으로 써도 이 몰들은 연동이 생기지 않는다. **KidItem 확장이 긁고 있는 몰들은 사방넷/셀피아/플레이오토 전부가 못 하는 영역**이고, 이게 대체 불가능한 자산이다.

## 6. KidItem이 취할 전략

### 원칙: API는 "대량 처리 수단"이 아니라 "무인화·안정성 수단"이다

API로 바꿔도 처리량은 안 는다(전부 건별 + 레이트리밋). 대신 **브라우저·로그인 세션·캡차·DOM 변경에 안 깨지고, PC를 안 켜둬도 돌고, 실패가 에러코드로 잡힌다.** 이 가치만으로 전환할 가치는 충분하다.

### 몰을 3티어로 나눈다

**A티어 — API 전면 전환 (11번가, ESM, 쿠팡)**
공식 API가 4기능을 다 커버하는 몰. 화면 자동화를 걷어낸다.

**B티어 — 화면 자동화 유지 (아이스크림·온채널·키즈노트·꼬망세·티처몰·키드키즈·도매꾹 등)**
API가 존재하지 않는 몰. 여기는 선택지가 없고, 동시에 KidItem의 차별점이다. 현재 확장 구조 유지.

**C티어 — 셀피아 전송**
화면 주입 유지. 약관 확인만 선행.

### 착수 순서 (권장)

**0단계 — 지금 당장, 코드 짜기 전에**
1. **ESM API 신청 메일부터 보낸다.** 유일하게 거절 가능하고 검수 게이트가 하나 더 있는 몰이다. 승인 기간 공식 수치가 없으므로 리드타임이 가장 길다. `etapihelp@gmail.com`
2. **고정 IP를 확정한다.** 3사 모두 IP 화이트리스트다(쿠팡 10개, 11번가 3칸, ESM 명시). **이게 아키텍처 분기점이다** — 현재 확장은 사용자 PC에서 돈다. API 호출은 **KidItem 서버에서** 나가야 하고, 그 서버 IP가 고정이어야 한다. 클라우드 오토스케일로 IP가 바뀌면 전 연동이 끊긴다.
3. **셀피아 약관 확인** (자동화 금지 조항 유무).

**1단계 — 11번가 (가장 쉽다)**
심사 없음 + 즉시 발급 + 무료. 여기서 API 파이프라인 골격(큐 워커 + 백오프 + 에러코드 매핑)을 먼저 만들고 검증한다. 주의: 키 1개뿐이니 용도 분리 불가, XML/EUC-KR, SKU 전역 유일.

**2단계 — ESM (승인 나면)**
1콜로 양사 동시 등록되는 이점이 크다. 대신 함정 5개(재고 0 불가, 1개월 자동삭제, 옵션상품 재고 API 불가, 3분 대기, 판매중지 시 가격수정 불가)를 **도메인 규칙으로 코드에 박아야** 한다. 마스터↔사이트별 상품번호 3-way 매핑 테이블 선행.

**3단계 — 쿠팡 (가장 마지막, 절단 전환)**
키 1개 + 연동업체/자체개발 배타 제약 때문에 **사방넷과 병행이 불가능**하다. 다른 몰들이 KidItem으로 다 넘어와 사방넷 의존이 최소화된 뒤에 마지막으로 스위치를 내리는 게 맞다. 연동정보 수정은 주 10회 제한이니 IP를 미리 확정하고 한 번에.

### 공통으로 반드시 넣을 것 5가지

1. **몰별 레이트리밋 프로파일 + 지수 백오프 큐.** ESM 주문조회 5초/1회, ESM 상품목록 분당 20회, 쿠팡 초당 5(안전하게 2~4), 11번가 미공개(보수적으로). 쿠팡은 `X-CAG-Warnings` 헤더를 읽어 선제 감속.
2. **델타 동기화.** 전 상품 스캔 금지. 변경분만 큐잉.
3. **키 만료 캘린더 + D-60/D-14 알림.** 쿠팡 180일(만료 14일 전부터 재발급 버튼 활성), 11번가 180일(호출하면 자동연장이라 사실상 안전하나 추적은 필요), ESM 미공개.
4. **부분 성공 전제 재시도.** 쿠팡 송장 배열은 건별 결과(`retryRequired`)를, ESM은 사실상 `3000` 하나로 다 내려오므로 **메시지 문자열 파싱**이 필요하다.
5. **택배사 코드 3중 매핑 테이블.** 쿠팡=문자열(`CJGLS`, 자릿수 검증까지), ESM=5자리 정수(`10013`), 11번가=미확인, 온채널=택배사명 문자열(`"CJ 대한통운"`), 도매꾹=`DAEHAN`. 이미 KidItem에 여러 체계가 섞여 있으니 **정규화 레이어를 하나 만들어 두는 게 낫다.**

### 셀피아는 건드리지 않는다
전송 방식을 바꿀 실익이 없다(코인 차감 동일, push API 부재). 대신 **약관 리스크만 해소**하고, 중장기적으로 "셀피아 자리를 KidItem이 흡수"하는 게 진짜 그림이라면 — 139개 몰 중 정산수집이 6개뿐이라는 점, B티어 몰들이 목록에 아예 없다는 점이 KidItem이 셀피아를 대체할 수 있는 근거가 된다.

## 7. 확인 안 된 것

**대표님께 "모른다"고 말해야 하는 것들** — 아래는 공개 웹에서 확인 실패했고, 로그인 후 확인하거나 직접 문의해야 한다.

**11번가**
- **일일 호출 상한의 실제 숫자.** 근거는 에러코드 `004 overedTraffic` 한 줄뿐. 리셋 시각, 초당/분당 제한, Retry-After 전부 미공개. → 판매자 계정 로그인 후 개발가이드 '공통 유의사항' 또는 묻고답하기 문의.
- **셀러API의 발송처리 엔드포인트·요청 규격·택배사 코드표·1회 최대 건수** — 공개 웹에 전혀 없음(셀러오피스 로그인 필요).
- 셀러API 페이지당 건수 상한, 조회 최대 기간. (공개된 건 일반 오픈API 상품검색 `pageSize` 최대 200뿐)
- **대량 상품등록 API 부재는 "정황 근거"다.** 공개 카탈로그 + 독립 구현체 5곳에서 배치 엔드포인트가 안 나왔다는 것이지, 로그인 후 가이드에 벌크 API가 있을 가능성은 배제 못 함.
- 상품 '목록' 조회 가능 여부가 상충 — 공식 소개는 *"목록을 가져올 수 있습니다"*, 서드파티 정리는 *"목록 API 없음, 단건 조회만"*.
- **약관 제6조 ④의 해석** — 자사 데이터 자체 DB 적재가 허용되는지. **가장 확인이 필요한 항목.**
- IP 화이트리스트 최대 개수, CIDR 지원 여부, 반영 소요시간.
- 180일 공지 본문(시행 연도·소급 기준일·유예기간) — 제목만 렌더링됨. 2026-06-30로 **추정**.

**ESM**
- **일일 총 호출 쿼터 존재 여부** — 확인된 건 분당(상품목록 20)·5초당(주문조회 1)뿐.
- **상품 등록/수정 API 자체의 rate limit** — 2026-08 공지가 부하 원인으로 "대규모 등록·수정"을 지목했으면서 제한은 조회에만 걸었다. 등록/수정 상한 수치 비공개.
- **Secret Key 만료 주기·로테이션 절차** — 인증 가이드에 만료 언급 자체가 없음.
- IP 등록 가능 개수·변경 절차·반영 시간·동적 IP 대응.
- 승인 소요 기간 공식 수치, 거절 커트라인(매출 하한 등).
- 주문조회·정산조회 `pageSize` 상한 (샘플에 100/1000이 보이나 공식 상한 미기재).
- **자체 개발 셀러가 '셀링툴 관리' 슬롯(상품/주문 각 5개)을 써야 하는지** — 공식 가이드는 신청 메일만 안내. 제3자 문서는 전부 셀링툴 업체 기준이라 대입 불가.
- `https://etapi.ebaykorea.com/`이 조사 시점 접속 불가(ECONNREFUSED) — IP 등록 절차가 더 구체적일 수 있음.

**쿠팡**
- **초당 기준 충돌 미해소** — 전역 정책 5/s vs 상품 API 문서 10/s. 엔드포인트별 별도 버킷인지 불명.
- **송장업로드 1회 최대 건수** — 문서에 없음. 실측 필요.
- "일 5,000건"이 옵션 단위인지 상품 단위인지 — 한글 *"옵션상품 기준"* vs 영문 *"5,000 products"* 불일치.
- `permittedCount` 산정 기준·상향 방법.
- 429 영구 차단 발동 조건(수치). 1차 출처가 쿠팡 공지 원문이 아니라 윈셀링 전재본.
- 연동정보 수정 제한이 **주 10회인지 월 10회인지** 출처 불일치.
- 송장 등록 마감 시한·판매자점수 차감 규칙.
- 로켓그로스 전용 상품 API의 옵션 상한·호출 제한(미조사). 로켓그로스 재고는 **조회(`분당 50회`)만 확인**, 수정 API 존재 여부 미확인.

**셀피아 / 플레이오토**
- **셀피아 Open API의 문서 URL·인증 방식·rate limit·키 정책** — 공개 근거 0건. 확인 경로는 셀피아 카카오채널(평일 10:00~18:00)뿐.
- **주문 업로드(push) API 존재 여부** — 공개 문서 언급 0건. "엑셀 업로드만 가능"을 웹 근거로 확정하지 못했다(사내 코드 근거는 있음).
- **'주문 코인 1건'의 정확한 차감 단위** — 1주문=1코인인지, 품목 수만큼인지, 합포장·취소반품 재수집이 어떻게 카운트되는지. 각주는 *"당일 기준으로 주문, 상품 전송 수가 카운트됩니다"*뿐. (검색 중 나온 "세트/사은품 미포함" 문장은 셀피아가 아니라 셀픽(SELLPICK) FAQ일 가능성이 커 **인용 불가**.)
- '자동 주문 수집'(월 5만원)의 수집 주기·동시 실행 수·재시도 정책 — 숫자 전무.
- 플레이오토 API의 작업카운트 단가·기본 제공량·호출 제한·키 만료·IP 등록 여부 — 개발자센터가 로그인 필요 SPA라 확인 불가.
- **'작업API'(쓰기 계열) 승인 조건** — *"고객센터 문의"* 외 자격·요금·거절 사유 전무. 외부에서 셀피아/플레이오토로 데이터를 밀어넣는 경로의 **핵심 병목인데 완전히 불투명**.
- **셀피아 이용약관 전문** — `guide2.html` HTTP 204로 읽기 실패. **자동화/매크로 금지 조항 확인 필수.**
- 사방넷 ↔ 셀피아 직접 연동 — 양측 문서 어디에도 언급 없음. **"연동 안 됨"이 아니라 "근거 없음"**으로 취급해야 함.
- 무료 플랜 한도 표기 불일치 — 셀피아 본사이트 LITE 500 vs 메이크샵 제휴 페이지 내에서 500/300 혼재. **계약 전 서면 확인 필요.**

**공통**
- **재고 변경이 실제 노출에 반영되기까지의 지연** — 4개 몰 어디에도 공식 수치 없음. 확인된 건 ESM "등록 후 약 3분", ESM 실시간 콜백 "약 5초 무응답 시 주문 진행"뿐.
- **국내 통합솔루션(사방넷/플레이오토/이셀러스)의 공식 재고연동 주기** — 벤더 페이지가 JS 렌더링/403이라 원문 확보 실패. **"10분 배치"는 구조적 추론이며 인용 근거가 없다.**
- 11번가·ESM의 **품절 → 재판매(해제) 대칭성** — 쿠팡(stop/resume)·ESM(isSell)·네이버(재고 복원)는 확인했으나 11번가 판매재개 규격·장기 중지 부작용 미확인.
- 세 몰 모두 **'송장 등록 취소(철회)' API 존재 여부 미확인.** 쿠팡은 수정만, ESM은 재호출 덮어쓰기만 확인.
