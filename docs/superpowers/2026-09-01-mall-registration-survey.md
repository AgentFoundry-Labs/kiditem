### 0-2. 등록할 상품 데이터가 사실상 없다

```
sourcing_candidates   4건 (전부 status=sourced)
master_products   4,159건 → brand 0 / category 0 / images 0 / description 0
```

마스터상품 4,159건은 셀피아 재고 기준으로 만들어진 껍데기다(코드+이름만).
**"수집상품 → 27개 몰 등록"의 입력이 현재 4건이다.**

### 0-3. 진짜 상품 데이터는 쿠팡 리스팅에 있다

```
channel_listings  1,689건 (쿠팡 Wing 1,230 + Rocket 459). 다른 25개 몰은 0건
  카테고리 1,228 / 브랜드 985 / 제조사 1,220 / raw_json 1,685 / 마스터 연결 871
  raw_json 키 29종: 브랜드·제조사·모델번호·카테고리·바코드·등록상품명·
                    노출상품명·구매옵션유형·검색옵션유형/값 …
```

**상품 마스터의 현실적 원천은 수집상품이 아니라 이미 쿠팡에 올린 1,228개 상품이다.**
"쿠팡 리스팅을 마스터로 승격 → 나머지 26개 몰로 전파"가 첫 시나리오여야 한다.
이것이 사방넷의 역매핑에 해당하는데, KidItem 은 그 데이터를 이미 갖고 있다.

### 0-4. KC 인증 정보는 어디에도 없다

DB 전체에 `kc` / `cert` / `safety` / `notice` 를 포함하는 컬럼이 **0개**다.
쿠팡 리스팅 raw_json 29개 키에도 인증 항목이 없다(WING 목록 export 에 안 담김).

4절이 정의한 15개 필드는 **전부 신규 수집 대상**이다. 공급사 자료나 몰 상세페이지에서
끌어와야 한다.

## 2. 솔루션 클러스터 — 어댑터 공유 기회

**이 보고서의 핵심 결론: 6개 클러스터 어댑터로 10개 몰(하이스토어·하프클럽 포함)을 덮는다.**

| # | 클러스터 어댑터 | 덮는 몰 | 몰 수 | 1몰당 절감 효과 |
|---|---|---|---|---|
| 1 | **shopby BPA** (partner.shopby.co.kr) | 떠리몰, 웅진클래스몰 | 2 | 로그인·메뉴·폼 구조 100% 동일. 단 대량등록 가부만 몰별 분기 |
| 2 | **퍼스트몰 selleradmin** | 티처몰, 체더스 | 2 | 동일 스킨 계열, `excel_provider_seq` 등 세션 규약 이미 검증됨 |
| 3 | **X2BEE 판매자 포털** | 아이스크림몰, 하이스토어 | 2 | po.hi-store.co.kr → po.i-screammall.co.kr **301 리다이렉트, 응답 바이트 19,484 동일** = 물리적으로 같은 인스턴스 |

**클러스터 공유가 불가능한 몰(단독 어댑터 필수)**: 온채널, 꼬망세, 키드키즈, 지니마켓, GS샵, 윤선생, 원폴라리스 — 전부 자체개발이거나 확인 불가.

- 아트공구: 우리 계정이 카페24 **공급사(supplier)** 계정 → 몰 운영자가 상품 권한을 부여하지 않으면 등록 자체가 불가

## 4. 어린이제품 규제 요건

### 4-1. KC 3단계 — 우리 취급군의 분기점

| 제도 | KidItem 해당 품목 | 인증번호 |
|---|---|---|

| **안전확인 (법 제22조)** | **완구, 학용품(문구), 유아용 섬유제품, 어린이용 자전거, 유아용 의자·침대, 합성수지제 어린이용품 등 17품목** ← 주력 | **신고번호 있음, 공개 DB 조회 가능** |

근거: [안전확인 대상](https://www.safetykorea.kr/policy/targetsSafetyCheck3) · [공급자적합성확인 대상](https://www.safetykorea.kr/policy/targetsSafetySupply) · [표시기준 시행규칙](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?popMenu=ov&csmSeq=690&ccfNo=4&cciNo=3&cnpClsNo=1)

⭐ **자동화 최대 분기**: 안전확인 / 공급자적합성확인 두 갈래를 상품 마스터에서 먼저 나누지 않으면, 가구·섬유 상품에서 인증번호 필드가 비어 등록이 통째로 실패한다.

### 4-2. 상품정보제공고시 카테고리 매핑

고시 카테고리에 **"완구"·"문구"는 존재하지 않는다.** ([고시 원문](https://www.law.go.kr/행정규칙/전자상거래등에서의상품등의정보제공에관한고시))

| 내부 분류 | 고시 카테고리 | 항목 수 | KC 항목 |
|---|---|---|---|
| 완구·교구 | 영유아용품 | 12 | **있음** ("KC 인증 필 유무") |
| 문구류 | 기타재화 | 5 | 있음 (인증·허가 확인 사항) |
| 전자식 사무기기 | 사무용기기 | — | — |
| (오매핑 주의) | 스포츠용품·악기 | 11 | **없음 — 완구를 여기로 넣으면 KC 항목이 통째로 누락** |

매핑 자체를 명시한 공식 문서는 못 찾음 → **매핑 근거 confidence: medium**. 항목 목록은 [고도몰 고시표](http://guide.godo.co.kr/guide/php/information.by.goods/information.by.goods.htm)로 확인.

### 4-3. 몰별 인증번호 입력 위치 (두 군데 모두 채워야 함)

| 몰 | 전용 인증 필드 | 특이사항 |
|---|---|---|
| 쿠팡 | 카테고리 메타 API의 `certifications[]` → `certificationType`, `dataType`(CODE/NONE), `required` | WING 화면은 인증번호 입력 후 **'검증' 버튼 → KATS DB 자동 대조**. 실패 시 등록 거부 ([문서](https://developers.coupang.com/hc/en-us/articles/360034035713-Category-Metadata-Query)) |

### 4-4. ⭐ 상품 마스터에 반드시 있어야 할 필드

영유아용품 고시 12항목이 사실상 스키마의 상한선이다.

| 필드 | 타입 | 필수 | 출처·용도 |
|---|---|---|---|
| `kcType` | enum(`SAFETY_CERT`/`SAFETY_CONFIRM`/`SUPPLIER_CONFORMITY`/`NOT_APPLICABLE`) | **필수** | 등록 분기의 근간. 쿠팡 `dataType`, 네이버 `childCertifiedProductExclusionYn` 결정 |
| `kcNumber` | string, nullable | 조건부 | `SUPPLIER_CONFORMITY`·`NOT_APPLICABLE`은 null 허용. **정규식 검증 금지**(부여규칙 미확인) |
| `kcCertBody` / `kcCertDate` / `kcCertCompanyName` | string / date / string | 조건부 | 네이버 `companyName`·`certificationDate`, shopby `^\|^` 복합필드용 |
| `usageAge` | string | **필수** | 법 제29조 사용연령 표시 의무 + 고시 6항 (체중범위 포함) |
| `noticeCategory` | enum(`INFANT_GOODS`/`OTHER_GOODS`/`OFFICE_EQUIP`/…) | **필수** | 고시 카테고리. 몰별 고시 코드 매핑 키 |
| `productName` + `modelName` | string | **필수** | 고시 1항 (쿠팡 `sellerProductName` 100자 제한 주의) |
| `sizeWeight` | string | 필수(영유아) | 고시 3항 |
| `color` | string | 필수(영유아) | 고시 4항 |
| `material` | string | 필수(영유아) | 고시 5항 |
| `releaseYearMonth` | string(YYYY-MM) | 필수(영유아) | 고시 7항 |
| `manufacturer` | string | **필수** | 고시 8항 (영유아·기타재화 공통) |
| `manufactureCountry` | string | **필수** | 고시 9항 (공통) |
| `precautions` | text | 필수(영유아) | 고시 10항 + 별표8 주의·경고 표시("보호자와 함께 사용", "3세 이하 사용금지") |
| `warrantyStandard` | text | 필수(영유아) | 고시 11항 |
| `asContact` | string | **필수** | 고시 12항 / 기타재화 5항 |

**사전 게이트 설계 원칙**: 어린이제품 안전 특별법 **제30조**가 "표시 없는 안전관리대상어린이제품의 판매 중개 금지"를 규정하고 있고 이것이 쿠팡·스마트스토어가 인증 미입력 상품 등록을 차단하는 법적 근거다. 따라서 **인증정보 누락 상품이 등록 거부되는 것은 정상 동작이며, 재시도 로직이 아니라 파이프라인 진입 전 사전 게이트로 걸러야 한다.**

제재: 표시 위반은 형사벌(3년 이하 징역 또는 3천만원 이하 벌금, 제41조), 표시 없는 제품 판매는 1천만원 이하 과태료, 주의·경고표시 미표시/연령기준 위반 판매/중개 금지 위반은 500만원 이하(제43조). ※ 조문 요지는 요약본 기반 — 금액·형량 인용 전 [law.go.kr 원문](https://www.law.go.kr/법령/어린이제품%20안전%20특별법) 재확인 권장.

**검증 API**: [공공데이터포털 국가기술표준원 제품 안전인증 및 리콜 정보](https://www.data.go.kr/data/15116894/openapi.do)가 어린이제품법 대상을 포함하나 API 유형이 `LINK`라 요청변수 목록 미확보. safetykorea 자체 Open API는 **이메일(safetykorea@korea.kr) 수동 신청**이며 인터페이스 설계서를 받아야 스펙 확인 가능. 어느 쪽도 착수 전 선행 작업이 필요하다.

## 5. 권장 구현 순서

난이도 × 커버리지로 정렬. **Phase 0을 건너뛰면 이후 전 단계가 등록 거부로 되돌아온다.**

### Phase 0 — 규제 게이트 (몰 무관, 선행 필수)
상품 마스터 15개 필드 + `kcType` 3분기 + 고시 카테고리 매핑 테이블. 여기가 안 되면 쿠팡 '검증' 버튼과 네이버 등록 제한에서 전량 튕긴다. 병행: 공공데이터포털 활용신청(개발단계 자동승인)으로 인증번호 조회 명세 확보.

### Phase 1 — 공식 API 저난이도 (커버 4몰, 난이도 low)
**네이버 → 토스쇼핑 → 롯데온 → 신세계 SSG.** 전부 문서 공개 + 자율 키 발급 + 상품등록 API 실재. 쿠팡은 사내 엑셀 구현이 이미 있다는 전제이므로 이 단계에서는 API 전환 검토만 병행(장기적으로 API가 유리).
선행 작업: 롯데온·네이버·11번가는 **호출 IP 화이트리스트 등록**이 공통 관문 — 4개 몰 몫을 한 번에 신청.

### Phase 2 — 클러스터 어댑터 (어댑터 3개 → 몰 5개)
1. **퍼스트몰 selleradmin** (티처몰 + 체더스) — 자사 확장이 이미 `/selleradmin/order_process/excel_down`으로 세션·폼 규약을 검증했다. 재사용 자산이 가장 두껍다.
2. **shopby BPA** (떠리몰 + 웅진클래스몰) — 떠리몰 엑셀 양식이 A~BU 컬럼 단위까지 문서로 확보되어 있어 착수 즉시 구현 가능. 웅진은 같은 어댑터 안에서 폼 모드로 분기.
3. **X2BEE PO** (아이스크림몰 + 하이스토어) — 301 리다이렉트로 단일 인스턴스가 실증됨. 다만 등록 화면이 미확인이라 **계정 로그인 후 재조사가 선행**.

### Phase 3 — 사방넷 미커버 전략 몰 (커버 4~5몰) ★ 전략 우선순위
사방넷 696개 지원몰에 **온채널·꼬망세·키드키즈·지니마켓·아이스크림몰이 없다.** 외부 솔루션으로 우회할 길이 없으므로 직접 구현이 유일한 경로이고, 그만큼 경쟁 방어력이 있다.
- **보리보리 + 하프클럽** — 공식 API가 있어 이 그룹에서 유일하게 난이도가 낮다. MD에게 인증키 요청이 **오늘 당장 할 수 있는 액션**. (단 카페24 마켓플러스·샵링커·이지어드민이 이미 붙는 경로이므로 "사방넷 미커버 = 완전 무경쟁"은 아님)
- **온채널** — 공급사 대량등록 엑셀 양식 존재, 주문수집으로 세션 검증됨. 함정 2개: 주소지(출고지/반품지) 사전 등록 없으면 상품등록 자체 불가, 승인요청 안 한 상품은 **익일 23:59 자동 삭제**.
- **꼬망세** — 파일 규약 `_<도메인>.<액션>.php` 확인(`/subAdmin/_product.list.php`, `_product.form.php`). 주문수집에서 쓴 폼 POST 패턴과 같은 계열일 가능성이 높다(추정).
- **키드키즈** — 입점 프로세스 STEP4에 '상품 등록'이 명시되어 있으나 전역 인증 가드로 외부 탐색이 완전히 막혀 있다. **파트너 계정 로그인이 유일한 진입로**.

### Phase 4 — 통합솔루션 경유 검토 (커버 2몰, 개발 없이)
**올웨이즈·베네피아**는 자체 어댑터를 만드는 대신 사방넷/플레이오토 연동이 공식 경로다. 올웨이즈는 플레이오토 전용 무료 가입 링크까지 제공한다. 자체 개발 대비 ROI를 먼저 계산할 것.

### Phase 5 — 고난이도 잔여 (커버 4몰)
11번가(셀러API 신청·IP 등록 지연 예상) → 카카오(제휴사 승인 필요) → 지마켓·옥션(마스터 ID + JWT) → GS샵(2026-03 개편으로 구 자료 전량 재검증) → 지니마켓(공개 자료 제로) → 키즈노트(본사 승인 플로우).

### Phase 6 — 정보 부족으로 착수 불가
**윤선생, 원폴라리스.** 담당자에게 실접속 도메인·판매자 계정을 받기 전까지는 조사 자체가 불가능하다. Phase 0 착수와 동시에 요청을 걸어둘 것.

**요약 커버리지**: Phase 1~3까지 완주 시 **13~14개 몰**(전체의 약 절반)을 어댑터 10개 이하로 덮는다.

### 6-2. 근거를 못 찾은 것
- **원폴라리스**: officeone.co.kr / onepolaris.co.kr **모두 DNS·접속 실패(HTTP 000)**. 가가몰 계열은 URL 패턴 일치에 근거한 **추정**이며 확정하지 않았다. 담당자에게 실제 접속 도메인을 받아야 재조사 가능.
- **꼬망세 현행몰 솔루션 벤더명**: seesawmall.dreamtec.co.kr과 코드베이스가 동일함은 실측했으나(URL 디스패치·상품코드 포맷·핸들러·JS 트리 일치), 벤더명이 화면·소스 어디에도 없어 미확인. 구몰의 프로즌(PROZN)은 현행몰이 아님이 확정(`/_prozn/` → 404).
- **롯데온 엑셀 대량등록**: 공식 매뉴얼 25p에 엑셀 업로드 절차가 없고, 별도 '일괄 수정' 매뉴얼은 화면 방식이며 등록이 아니다. "없다"가 아니라 "근거를 못 찾았다".
- **KC 인증번호 부여규칙**: 시행규칙에서 부여방법 조문을 찾지 못했다. 관측된 예시(`CB061T092-4011A`)는 있으나 **정규식 검증 로직의 근거로 쓰면 안 된다.** safetykorea Open API 응답 샘플로 역추론할 것.
- **공급자적합성확인 신고 시스템**([confirm.kips.kr](https://confirm.kips.kr/))에 어린이제품이 포함되는지·신고번호가 부여되는지 — PDF 파싱 실패로 미확인 (confidence: low).
- **쿠팡 어린이제품 전용 `certificationType` 코드값**: 문서에서 확인된 실제 예시는 `NOT_REQUIRED`, `KC_HOUSEHOLD_CERTIFICATION` 둘뿐. 실제 카테고리 메타 조회로 덤프해 확정해야 한다.
- **safetykorea / 공공데이터포털 API의 인증번호 단건 조회 파라미터 지원 여부**: 양쪽 다 명세 미확보.
- **전자상거래법상 상품정보제공고시 위반 제재 수준**: 미확인.
- **올웨이즈 자체 엑셀 양식 / 공식 OpenAPI**: 근거 페이지가 HTTPS 인증서 오설정으로 직접 접속 실패, 웹 아카이브(2024-02-21) 스냅샷 기준. 최신 시점에 자체 양식이 추가되었을 가능성은 배제 못 함.
- **뚝딱샵(ddddshop.co.kr)**: firstmall/cafe24/shopby 지문 모두 0. 별도 스택으로 보이나 미확인.

### 6-3. 전제로 받았을 뿐 검증하지 않은 것
- **쿠팡 사내 엑셀 일괄등록 구현 존재**: 오케스트레이터가 준 전제이며, 공개 출처로 확인한 사실이 아니다. 공개 문서상 확인된 공식 경로는 OpenAPI뿐.
